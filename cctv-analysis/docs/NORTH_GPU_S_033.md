# 0.3.3 선택형 북쪽 GPU 기능 · 평가와 검증

## 변경 범위와 연동

기본 실행과 AnalysisService API는 0.3.2를 유지한다. `gpu_profile.py`는 `north-gpu-s`를 직접 선택한 경우에만 공식 s 가중치 SHA-256·CUDA를 확인하고 기존 `AnalysisService.start`에 북쪽·cuda:0·가중치를 전달한다. 남쪽·동쪽에 s를 자동 선택하지 않는다. 기본 실행의 사용자 가중치·장치·설정 선택도 유지된다.

`waiting_audit.py`는 확정 관측+확정 유예와 CSV의 일치를 검사하는 **검증 보조 코드**다. 후보 대기를 더하거나 출입·대기 계산을 바꾸지 않는다. `verify_paced_input_033.py`는 기존 저장 측정 자료의 검증용이며 기본 분석 경로에서 호출하지 않는다. 버전과 runtime profile package-data를 추가했다.

```python
from cctv import AnalysisService
from cctv.gpu_profile import start_north_gpu_s

def main():
    with AnalysisService() as service:
        job = start_north_gpu_s(service, owner="team-app", video_path="inputs/north.mp4",
                               model_path="models/yolo11s.pt", output_dir="runs-s",
                               profile="demo", end=3.25)
        for record in job.records():
            print(record)
        print(job.status())

if __name__ == "__main__":
    main()
```

Windows spawn 보호문을 유지한다. 기본 n/사용자 설정 연동은 [데이터 계약](DATA_CONTRACT.md)과 기존 `examples/analyze_video.py`를 사용한다. 시연 초기값·가상 촬영시각·1초 CSV를 사용하는 `demo`를 실제 운영 가정으로 해석하지 않는다. `operating`의 초기 인원 등은 운영자가 설정해야 한다.

## 고정 전체 개발 영상 평가

기존 수동 이벤트 정답은 북쪽 20·남쪽 7·동쪽 14건, 총 41건이다. 동일 방향·±1초·일대일 매칭이며 합산은 환경별 TP/FP/FN을 합친 micro 지표다. 북쪽 s / 남·동 n, imgsz 640·NMS IoU 0.7·confidence 0.1·기존 ByteTrack·0.3.2 구역/출입/대기 규칙을 사용한다. 정답·허용오차는 바꾸지 않았다.

**통과 추정 시각 기준**으로 합산 +3.55%p, 북쪽 +6.54%p다. 자동 확정 시각 점수와 섞지 않는다. 최종 통과 FN13의 직접 실패 단계는 출발·목적지 관측 근거 부족 11건, 실제 인물 대응 미확정 2건이다. 확정만 추가 FN인 7건은 이벤트가 있어도 확정 시각이 평가창을 벗어난 경우이며 별도 물리적 누락 7명으로 세지 않는다.

기존 전체 이벤트·정답의 동결 해시와 저장 평가를 대조해 재사용했다. 이번 업로드에서 재학습·앙상블·랜덤포레스트·새 정확도 실험·전체 재추론은 하지 않았다. 실패/미채택 실험과 미완료 수동 박스 정답은 배포에 넣지 않았다.

## 실행 검증과 재사용 범위

- Windows x64·Python 3.13.9·RTX 4060. 북쪽 s 실제 CUDA FP32(fp16=false) 확인. torch 2.14.1+cu132, torchvision 0.29.1+cu132, ultralytics 8.4.177, OpenCV 5.0.0.93, numpy 2.5.4, lap 0.5.13, av 19.0.1.
- 기존 전 환경 n 보관 결과는 CUDA 장치 기록은 있으나 실제 backend dtype 기록이 없다. 북쪽 별도 GPU n/s 전체 비교는 모두 FP32를 확인했으며 북쪽 지표가 동일했다. 원래 보관 결과의 정밀도를 사후 단정하지 않는다.
- 설치 wheel 기본 n CPU 30프레임·1레코드, 선택형 s GPU 78프레임·3레코드 통과. 최종 API/종료/옵트인 회귀 15테스트 통과 기록과 이후 s 78프레임·3레코드 점검을 재사용한다.
- 설치본·wheel·ZIP과 안정 소스 런타임 61파일 일치 기록을 재사용하고 업로드 소스는 줄바꿈 정규화 후 다시 대조한다. ZIP 내부 wheel도 별도 wheel과 동일하다. 문서·설치 메타데이터 README는 배포 당시 기록이므로 현재 짧은 웹 README와 문구 차이가 있다. 배포물은 재빌드하지 않는다.
- 북쪽 s 전체 2524프레임·105 CSV행·입장6/퇴장10·최종 내부25 확인. 전체 렌더링은 검증된 GPU 저장 관측의 기존 API 재생 산출물이며 새 추론으로 주장하지 않는다. 원본/결과 영상·전체 로그/CSV는 공개 업로드하지 않는다.
- 별도 전체 단일 입력 paced 시험의 CSV flush 지연 p50 27.83ms / p95 37.01ms / 최대 42.16ms, 미처리0. 준비시간은 worker 분석 진입→ready 12.642초, 입력 시작 12.742초로 별도다. 로컬 파일 기록 측정이며 네트워크 전달 지연 보장은 아니다.

**개발 영상 평가이며 별도 영상 일반화는 미검증**이다. 가림·박스 하단 변화·ID 유실·짧은 구역 관측으로 누락될 수 있다. 내부 인원·빈칸·대기시간은 초기값과 이용시간 가정의 추정치다. 다른 GPU/드라이버·OS·실제 CCTV 수신·동시 세 입력·장시간 실시간 기록 지연은 별도 검증이 필요하다.
