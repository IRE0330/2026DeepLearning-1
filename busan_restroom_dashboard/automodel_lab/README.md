6. 가장 좋은 모델+변수 범위+설정값, 사용/제외 항목, 날짜·시간별 예측표·그래프를 확인하고 엑셀·CSV로 저장합니다. 전체 결과 ZIP에는 탐색표, 모델, 평가 결과, 자동 추정한 미래 입력값도 포함됩니다.

미래는 마지막 기록 이후에만 선택 가능합니다. 날짜만 멀리 선택하면 마지막 기록부터 그 날짜까지도 순서대로 계산합니다. 최대 10,080개 미래 시점(1분 기록이면 약 7일, 1시간 기록이면 약 420일)입니다. 이 범위는 계산 제한이지 장기 예측 정확도를 보장하는 기간이 아닙니다. 긴 기간은 실행 시간이 늘고 오차가 누적됩니다. 선택 기간 끝 이내의 원래 기록 간격에 맞는 시점만 표시됩니다.

데이터 조건: 대상별 최소 80개 기록, 규칙적인 분 단위 간격, 같은 대상·시각 중복 없음. 여러 대상은 동일한 시작·종료 시각. 누락/중복은 임의로 보간하지 않고 오류로 알립니다. 과거 기록은 별도 날짜 범위로 조회할 수 있습니다.

## 여러 파일을 함께 사용하기

파일 선택창에서 여러 파일을 고르거나 추가로 끌어 놓으세요. 같은 컬럼 구성이면 기록을 행으로 합칩니다. 서로 다른 컬럼 구성이면 공통 날짜·시간·ID 항목으로 기준 파일에 연결합니다. 합친 뒤 동일한 자동 분석·최적 조합 탐색·미래 예측이 실행됩니다.

'파일 합치기 설정'에서 행 합치기/항목 연결을 직접 바꾸고 기준 파일과 연결 항목을 수정할 수 있습니다. 항목 이름이 다르면 기준 파일의 날짜 항목과 상대 파일의 날짜 항목처럼 같은 뜻의 항목을 같은 순서로 지정하세요. 각 엑셀 파일은 선택한 시트 한 개를 읽습니다.

기준 파일의 행을 유지하는 왼쪽 연결입니다. 상대 파일은 연결 항목 조합이 유일해야 합니다. 모호한 다대다 연결이나 하나도 일치하지 않는 연결은 자동 진행하지 않습니다. 일부만 연결되면 미일치 행 수를 알리고 해당 추가 입력은 빈 값으로 둡니다. 연결 뒤 빈 값은 모델 전처리에서 처리되므로 날짜·시각 단위와 범위를 확인하세요. 내용이 완전히 같은 중복 행은 기본 제거합니다. 연결이 타당한지는 데이터의 의미를 기준으로 확인해야 합니다.

## 자동화되는 전체 과정

### 1. 데이터 분석·정리

학습 구간의 빈 값, 고유값 수, 자료형을 분석합니다. 추가 입력 중 빈 값 95% 초과·상수·거의 매번 다른 문자 ID/긴 글은 자동 후보에서 제외하고 이유를 기록합니다. 목표와 시간의 빈 값은 임의로 만들지 않습니다. 숫자 입력은 중앙값 대치·표준화, 범주는 결측 대치·원핫(최대 범주 40)으로 처리합니다. 전처리는 각 학습 구간에서만 학습합니다.

### 2. 날짜·과거 패턴 특성 자동 생성

연·월·일·요일·주말·연중일·연중 주차·월초·월말, 시간대/요일/월의 sin/cos 주기를 만듭니다. 목표의 1/2/3/6/12칸 전 값, 3/6/12칸 이동평균·변동폭, 최근 변화도 생성합니다. 기록이 충분하면 하루 전·일주일 전 값을 추가합니다. 이동 통계는 예측 시각 이전 값만 사용합니다.

요일이 '반드시 영향을 준다'고 가정하지 않습니다. 후보로 만들고 검증 결과에 따라 유용한 조합을 선택합니다. 기본 한국 공휴일·대체공휴일 달력으로 공휴일 여부·명칭·휴일 전후·주말 또는 공휴일·징검다리 평일을 자동 생성합니다. 고급 설정에서 미국/일본/사용 안 함으로 바꿀 수 있습니다. 국가별 특별행사나 운영 중단은 별도 예정 정보가 필요합니다.

### 3. 변수 조합과 모델 설정의 공동 탐색

전체 항목(100%)과 학습 데이터의 관련성(MI) 상위 25/50/75%를 후보로 삼습니다. 모델별 설정 후보와 변수 사용 범위를 결합해 고정 난수의 예산 탐색을 수행합니다. 각 모델의 전체 항목 기준 후보를 먼저 포함하고 남은 예산에서 다양한 조합을 평가합니다.

예: Random Forest의 깊이·최소 잎 수·사용 특성 비율, Ridge의 규제 강도, 부스팅의 학습률·트리 구조·반복 수, KNN 이웃 수 등. 탐색 횟수가 늘수록 더 많은 조합을 봅니다. 모든 가능한 변수 부분집합이나 모든 실수 설정값을 전수 탐색하는 기능은 아닙니다. MI는 인과관계가 아니며 변수 사이의 복잡한 상호작용을 놓칠 수 있으므로 전체 입력 후보도 비교합니다.

### 4. 여러 시간 구간으로 검증·선택

미래 예측은 확장형 시간 검증 두 구간을 사용합니다.
- 앞 50%로 학습 → 다음 구간 예측
- 앞 65%로 학습 → 다음 구간 예측
- 두 구간의 MAE 평균이 가장 작은 조합 선택. 같으면 입력 수가 적은 조합 우선.
- 모델과 선택 규칙을 고정하고 앞 80% 재학습 → 마지막 20%에서 최종 평가
- 선택을 바꾸지 않고 전체 기록 재학습 → 요청 날짜 예측

탐색 시 각 검증 구간은 요청 기간·이용 가능 구간 중 짧은 길이로 재귀 예측합니다. 최종 테스트 길이는 요청 기간과 마지막 20% 중 작은 값입니다. 요청 기간 전체를 검증하지 못하면 보고서에 알립니다. 최종 재학습에서 관련성 순위가 달라져 실제 선택 항목도 달라질 수 있습니다. 사용/제외 표는 최종 모델 기준입니다.

### 5. 다른 입력 변수의 미래 값도 자동 추정

과거 파일에 있는 다른 항목을 기본 후보에 포함합니다. 온도처럼 미래 값이 아직 없으면 각 예측 시작 시각 이전 기록으로만 보조 예측합니다.
- 숫자: 최근값/중앙값/단기 추세/일일 또는 주간 프로필 중 과거 내부 검증 오차로 선택. 계절 프로필은 기록 기간이 충분할 때 사용.
- 문자 범주: 과거 요일·시간별 최빈값, 부족하면 전체 최빈값.

검증·테스트에서도 동일하게 미래 입력을 추정하므로 실제 미래 관측값을 몰래 쓰지 않습니다. 이 추정값을 입력해 목표값을 순서대로 재귀 예측합니다. 보조 예측 방법과 자동 제외 항목을 화면과 보고서에 남깁니다.

**보조 예측은 실제 기상 예보·운영 일정이 아닙니다.** 기상 급변, 임시 휴무, 정책 변경 등을 알 수 없습니다. 정확한 미래 정보가 있다면 접힌 '데이터 분석과 변수 설정'에서 해당 항목을 지정하고 미래 파일을 올리세요. 시간·구분·항목 이름은 학습 파일과 같아야 하며 마지막 기록 다음부터 종료까지 모든 대상·시각의 값이 필요합니다. 양식 엑셀을 받아 채울 수 있습니다. 실제 미래 목표값은 불필요합니다.

## 탭 없이 한 번에 최적 조합 선택

기본 화면에는 탭이 없습니다. 파일 업로드 → 예측할 항목 선택 → (시간 데이터면 원하는 날짜 선택) → **최적 조합 찾고 예측하기** 한 번으로 실행됩니다. 결과 상단에 최적 모델·항목 조합, 사용 항목 수, 검증 평균 오차, 별도 최종 평가 오차를 보여줍니다. 선택한 모델의 구체적인 설정값과 최적 조합 요약 JSON도 저장할 수 있습니다.

날짜·시간이 없거나 목표가 문자 범주라면 동일한 화면에서 일반 표 분석으로 자동 전환합니다. 회귀/분류 유형과 입력 후보는 고급 설정에서 수정할 수 있습니다. 숫자 회귀는 MAE 최소, 분류는 macro F1 최대입니다. 일반 표 분석은 학습/검증/최종 테스트 60/20/20 한 번의 분리이며, 미래 예측의 두 구간 시간 검증과 다릅니다. 시간 정보가 자동으로 발견되면 일반 표 분석에서도 시간순으로 분리합니다. 날짜가 없는 자료만으로 미래 날짜 예측은 할 수 없습니다.

일반 표 결과에는 별도의 평가 기록 예측값이 표시됩니다. 접힌 메뉴에서 동일한 모델로 새 파일을 예측할 수 있습니다. 일반 표 모델과 미래 시계열 모델은 입력 구조가 달라 서로 호환되지 않습니다. 모델을 저장할 때는 같은 코드·패키지 환경을 보관하세요. 이 버전은 업로드한 임의 joblib을 실행하는 별도 탭을 두지 않습니다.

## 모델과 실행 비용

기본 일반 회귀 17개·분류 14개(기준 모델 포함), 시간 패턴 전용 후보 6개를 지원합니다. 미래 예측 기본 후보는 기존 모델과 Huber/Bayesian Ridge, 최근 값·요일 시간 패턴·Fourier·ETS를 포함합니다. 기록이 충분하면 일간·주간 반복도 기본 비교합니다. 다른 모델도 고급 메뉴에서 선택할 수 있습니다. 선택 설치 XGBoost/LightGBM/CatBoost:

```bash
python -m pip install -r requirements-extra.txt
```

선택 패키지가 설치되지 않으면 해당 시도는 알림과 함께 제외합니다. 플랫폼이나 Python 버전에서 설치가 안 되면 기본 모델로 실행하세요. MLP/SVM과 긴 시계열·많은 탐색은 시간이 걸립니다. 미래 예측은 각 설정마다 학습 창과 2개 검증 구간을 비교하고 직접 예측·결합 후보도 평가하므로 표시한 기본 예산보다 많은 학습이 필요합니다. 종료는 터미널 Control+C.

## 예측 차이가 큰 경우를 위한 추가 후보

- 최근 값 기준: 가장 최근 값을 유지하는 기준선.
- 일간 반복: 하루 전 값의 패턴을 반복. 기록 간격과 일 주기가 맞고 검증할 과거 기록이 충분해야 합니다.
- 주간 반복: 일주일 전 값의 패턴 반복. 충분한 주간 기록 필요.
- 요일·시간 패턴: 요일/시간대 평균을 전체 일간 패턴으로 완화하는 프로필.
- Fourier 계절 회귀: 일/주/연 주기 sin/cos와 선택적 추세를 Ridge로 학습.
- ETS 지수평활: statsmodels의 가법 계절/완화 추세 모델. 과거가 부족하거나 주기가 너무 크면 비계절 평활 사용.
- 일반 회귀 추가: Huber Regression, Bayesian Ridge, Bagging. 분류에도 Bagging 추가.

시간 패턴 전용 모델은 목적상 과거 목표값/달력만 쓰며, 선택된 입력과 제외 이유를 별도로 표시합니다. ML 변수 선택 모델과 같은 시간 구간에서 비교하고 가장 좋은 후보를 선택합니다. 시계열 전용 모델에서는 25/50/75% 변수 조합을 중복 탐색하지 않고 해당 모델의 실제 설정값만 탐색합니다.

결과의 '실제 기록과 예측이 얼마나 달랐나요?' 메뉴에서 마지막 평가 구간의 실제/예측 그래프와 시점별 차이를 볼 수 있습니다. 사용자가 별도로 가진 미래 실제값을 자동으로 읽는 기능은 아니며, 그 비교는 해당 실제 파일이 필요합니다.

새 통계 모델을 쓰려면 `python -m pip install -r requirements.txt`를 다시 실행하세요. 새 모델이 실제 데이터에서 기존보다 좋다는 보장은 없으며, 어떤 후보가 더 나은지는 동일 구간의 검증 결과로 결정합니다.

## 공휴일·주말 자동 입력

주말/요일은 날짜에서 계산하고, `holidays` 패키지의 선택 국가 달력(기본 한국, 대체공휴일 포함)을 사용해 공휴일 정보를 추가합니다. API 키가 필요 없으며 패키지 설치 이후 예측 중 인터넷 호출도 없습니다. 과거 학습 시각과 미래 예측 시각 모두 같은 규칙을 적용합니다.

항목: 공휴일 여부, 공휴일 이름, 공휴일 전날/다음날, 주말 또는 공휴일, 징검다리 평일. 징검다리는 휴일 사이 평일이라는 달력상 표시이며 실제 휴무로 간주하지는 않습니다. 이 값들이 항상 영향을 준다고 고정하지 않고 변수 조합의 후보로 비교합니다.

요일·시간 프로필과 Fourier 회귀도 공휴일 입력을 사용하도록 확장했습니다. ETS·단순 일간/주간 반복·최근 값 기준은 고유한 시계열 구조를 유지하며 공휴일 입력을 직접 사용하지 않습니다. 최종 선택 항목표에서 실제 사용 여부를 확인할 수 있습니다. 국가별 임시공휴일은 설치된 달력 버전이 아는 범위로 반영되며 지역 행사·기상 악화·임시 운영 중단까지 자동으로 알 수는 없습니다.

새 파일로 교체한 후 `python -m pip install -r requirements.txt`를 다시 실행하세요.

## 해석과 한계

- 결과는 이번 데이터·탐색 예산·검증 조건에서 고른 최적 조합입니다. 세계적으로 가장 좋은 모델을 보장하지 않습니다.
- 더미 점수는 생성 규칙 재현 성능이며 실제 부산역 성능의 근거가 아닙니다.
- 보조 변수와 장기 재귀 예측 오차는 누적됩니다. 불확실성 구간은 제공하지 않습니다.
- 특별행사·지역 운영 일정 자동 수집, 임의 텍스트/이미지/영상 학습, 불규칙 시계열 처리, 미래 외생변수의 완벽한 자동 판단은 포함하지 않습니다.
- 예측 시점에 알 수 없는 실제 결과·미래 정답을 입력 후보로 두면 누수가 생길 수 있습니다. 이를 이름만으로 완벽히 식별할 수 없으므로 원본 컬럼의 의미는 확인하세요.

## 범용 미래 예측 개선판

- 변수 조합·모델 설정 후보마다 전체 학습 기록과 최근 28일·84일에 해당하는 학습 창을 비교합니다. 최근 창은 대상별 최소 80개이며, 모든 검증 시작점에서 사용할 만큼 데이터가 있을 때만 후보에 추가됩니다. 과거 지연값은 학습 창 이전의 관측 기록도 참고할 수 있습니다.
- 요청 길이 전체가 최종 평가 이전에 두 번 들어가면, 서로 겹치지 않는 두 검증 구간에서 그 길이만큼 재귀 예측합니다. 기존 96개 검증 제한을 제거했습니다. 부족하면 짧은 검증 길이와 알림을 표시하며 전체 기간 검증으로 표시하지 않습니다. 최종 평가는 별도 마지막 20%의 시작점에서 요청 길이 또는 남은 기록만큼 수행합니다.
- 요일×시각 범주, 충분한 기록이 있을 때 하루·1주·2주·4주 지연값과 계절 지연값 평균을 생성합니다. 어떤 변수를 사용할지는 각 학습 구간에서 결정합니다.
- 검증 평균 MAE가 좋은 서로 다른 모델 계열 최대 3개를 골라, 상위 2개 및 3개의 동일 가중 평균을 별도 재귀 검증합니다. 결합도 단일 후보와 같은 기준으로 경쟁하며, 더 나쁜 결합은 선택되지 않습니다.
- 결과에는 학습 기간 후보와 요청 길이 전체 검증 여부가 표시됩니다. 최적 조합 요약과 저장 모델에도 학습 창 또는 결합 구성 설정을 포함합니다.
- 탐색 횟수 설정은 기본 변수·모델 설정 예산입니다. 실제 실행은 학습 창 후보 수만큼 증가하고 결합 후보가 추가되어 처리 시간이 길어질 수 있습니다.
- 이 변경은 예측이 더 좋아지는 후보를 탐색하는 기능이며 모든 데이터에서 정확도 향상을 보장하지 않습니다. 이번 정답 구간은 최적화 입력에 넣지 말고, 성능 개선은 별도의 새로운 기간에서도 확인하세요.

추가 검증: `python test_adaptive.py` (대상별 학습 창, 168시간 전체 검증, 모델 결합, 최종 정답 변경 시 선택 불변, 저장/복원).


## 버전 2.1: 직접 예측·최근 가중치·편향 보정

- 기존 재귀 모델 외에 달력 정보로 각 미래 시점을 독립적으로 예측하는 최근 가중 요일·시간 패턴, 달력 Extra Trees 후보 6개를 자동 비교합니다. 미래 목표값의 예측을 입력으로 재사용하지 않습니다.
- 최근 가중치의 반감기는 14/28/84일 후보입니다. 모델별 지원 설정을 비교하며 특정 데이터에만 적용하는 요일 강제 보정은 없습니다.
- 보정 후보는 각 학습 구간의 앞 80%로 예측하고 뒤 20%에서 대상·요일별 잔차를 구합니다. 관측이 적은 보정값은 0쪽으로 축소하고 전체 학습 구간으로 다시 학습합니다. 외부 검증 구간과 미래 정답은 보정 학습에도 사용하지 않습니다. 보정 없는 후보와 동일한 과거 검증으로 경쟁합니다.
- 직접 예측 후보는 날짜·사전에 제공한 미래 예정 정보만 사용합니다. 과거 외생 변수의 자동 추정값과 목표값 지연 특성은 제외합니다. 요일 패턴 방식은 대상·요일·시각·공휴일만 사용합니다.
- 재귀 트리의 소규모 예측은 작업자 생성 오버헤드를 줄이도록 단일 작업자로 실행합니다.
- 화면 상단과 요약 JSON에 2.1 버전을 표시하고, 버전이 바뀌면 이전 화면 결과를 재사용하지 않습니다. 결과 상단에 실제값 비교용 CSV 다운로드 버튼과 기간·행 수를 표시합니다.
- 개별 데이터의 미래 오차 개선은 보장하지 않으며, 기록되지 않은 행사·휴업·날씨 변화는 달력만으로 알아낼 수 없습니다.
- `test_direct.py`: 목표 지연값 변경에 대한 직접 예측의 불변성, 최근 가중치, 보정, 항목 설명, 저장·복원을 확인합니다.


주차장 비교 재현: `python benchmark_parking.py --train /경로/01_train.csv --answer /경로/02_actual_do_not_train.csv`
이 비교는 기본 설정 예산 8개, Extra Trees·Hist Gradient Boosting·주간 반복·요일시간 패턴·Fourier 5계열에 학습 창과 직접 예측·결합 후보를 추가한 별도 실행입니다. 화면 기본 예산 24개와 모델 후보 목록은 다르므로 결과가 달라질 수 있습니다. 정답 파일은 최적 조합을 선택한 이후에만 읽습니다.


## 버전 2.2: 이상치 영향 완화와 공휴일 분리

- 기존 원본 유지 후보를 보존한 채 공휴일 분리, 극단값 완화, 극단값 가중치 축소 후보 8개를 추가로 검증합니다. 항상 처리하는 것이 아니라 과거 검증 MAE가 작은 후보를 선택합니다.
- 비교 그룹은 대상×요일×시각×공휴일 여부입니다. 각 학습 구간의 그룹 내 관측이 8개 미만이면 그대로 둡니다. 충분하면 중앙값±6×강건척도(MAD/IQR, 건수 변동을 고려한 척도 하한 포함) 밖을 의심값으로 표시합니다. 극단값이 오류라고 확정하지 않습니다.
- 완화 후보는 학습 목표값만 경계까지 조정합니다. 가중치 후보는 목표값을 유지하고 의심 관측의 학습 가중치를 0.1배로 낮춥니다. 원본 파일은 수정하거나 삭제하지 않습니다. 직접 예측 후보에서 적용하므로 재귀 지연값을 임의로 보정하지 않습니다.
- 공휴일 분리 패턴 후보는 일반 일·요일 패턴을 만들 때 공휴일을 제외합니다. 달력 트리 분리 후보도 일반 날과 공휴일을 각각 학습합니다. 오차 보정의 잔차 역시 공휴일 여부를 나눕니다. 특정 공휴일별 별도 학습은 하지 않습니다.
- 미래에 해당하는 휴일 유형이 학습에 전혀 없으면 관측된 다른 유형을 대체 기준으로 사용합니다. 실제 휴업/수집 장애/정상적인 급증은 값만으로 확정할 수 없습니다.
- 원본 유지 후보나 결합 모델이 선택되면 모든 구성에 공휴일 분리/이상치 처리가 적용되지는 않을 수 있습니다. 결과의 ‘이상치·공휴일 처리 내역’에서 실제 선택된 구성별 방식·의심값수·예시를 확인하세요. off 모드는 탐지를 실행하지 않아 의심값수를 null로 표시합니다.
- 처리 기준은 각 검증 시작 이전의 학습 기록에서만 계산합니다. 평가용 실제값은 극단값도 삭제/보정하지 않습니다. 내부 오차 보정의 평가용 잔차도 원래 실제값을 사용합니다.
- 추가 후보로 실행 시간이 늘어납니다. 이전 benchmark 폴더와 별도 504시간 검증 결과는 버전 2.1 실험 기록이며 2.2의 개선 성능으로 해석하면 안 됩니다. 이 버전의 정확도 개선 여부는 재실행 결과로 확인해야 합니다.
- 테스트: `python test_robust_calendar.py` — 표본 부족 유지, 극단값 완화/가중치, 원본 불변, 공휴일 값 변화에 대한 일반 요일 예측 불변성, 평가 극단값 유지, 모델 선택/저장 확인.


## 버전 2.3: 검증 확대와 MAE 중심 후보

- 충분한 기록이 있으면 최대 4개 검증 시작점을 시간상 떨어뜨려 배치합니다. 검증 구간은 서로 겹치지 않으며, 각 구간은 요청한 예측 길이를 평가합니다. 최근 학습 창 후보를 비교할 기록도 확보한 뒤 시작점을 정합니다. 마지막 20%의 별도 평가 구간은 모델 선택에 사용하지 않습니다. 부족하면 2~3구간 또는 짧은 검증으로 축소하고 실제 길이를 표시합니다.
- 결과와 best_combination.json에 각 검증의 학습 종료·검증 시작·검증 종료·시점수를 표시합니다. 여러 구간의 MAE를 평균해 변수·학습 기간·모델·결합 조합을 선택합니다.
- 최근 4주 동일 요일·시각의 산술 평균과 중앙값을 각각 정식 후보로 추가했습니다. 7일 이내 예측은 t-7/14/21/28일의 관측값을 사용합니다. 더 긴 예측은 예측 시작 이전의 최근 동일 요일·시각 관측값을 반복 사용하며 예측값을 과거 기록에 섞지 않습니다.
- 최근 4주 기준 후보는 공휴일을 제외하지 않는 단순 기준입니다. 공휴일 분리 후보도 따로 경쟁합니다. 4주 기록이 부족하면 관측된 주만 사용하고 동일 시각이 없으면 학습 요일·시각 패턴으로 대체합니다. 부족 여부는 알림과 후보 설명에서 확인하세요.
- 공휴일을 분리한 최근 가중 중앙값 시간 패턴 후보 3개와 HistGradientBoosting(loss=absolute_error) 직접 예측 후보 2개를 추가했습니다. 중앙값은 같은 학습 그룹의 절대오차를 최소화하는 기준이지만, 미래 오차 개선을 보장하지 않습니다.
- 이상치 완화·가중치 축소·공휴일 분리·직접 예측·모델 결합 기능은 유지합니다. 원본 및 평가용 실제값은 변경하지 않습니다.
- 검증 구간 및 후보 증가로 실행 시간이 더 걸릴 수 있습니다. 기본 예산은 기존 변수·모델 설정 수이며 추가 후보·학습 창·검증 구간은 별도로 실행됩니다.
- 검증: `python test_mae_candidates.py` (정확한 4주 평균/중앙값, 7일 이후 고정된 과거 기준, 예측값 재입력 없음, 절대오차 학습 설정, 겹치지 않는 검증 구간, 저장·복원).
