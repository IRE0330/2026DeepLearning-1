# CCTV 거리 기준선 시연

이 기능의 모든 혼잡도·대기시간은 **임의 거리 기준 시연값**입니다. 실제 미터 거리, 실제 대기시간 예측이나 감지 정확도를 보장하지 않습니다.

## 사용 방법

1. 메인 대시보드의 영상·모델 분석 설정에서 북쪽·동쪽·남쪽 원본 영상을 연결합니다.
2. 공통 설정 `configs/distance_reference.json`과 동일한 원본이면 PC 경로와 관계없이 자동 적용됩니다. 세 원본 검증 후 기준선 편집 컨트롤은 숨기며 영상 위 기준선은 계속 표시합니다. 공통 설정에 없는 영상의 기준선을 지정할 때는 **시연 설정 → CCTV별 5m·10m·15m 기준선**에서 CCTV를 선택합니다.
3. 사용할 영상 시점을 고르고, 입구 쪽 **대기줄 시작점**을 한 번 클릭합니다.
4. 시작점에서 줄이 길어지는 방향으로 **5m → 10m → 15m** 각 선의 양 끝점을 클릭합니다. 선은 대기줄의 전체 폭을 가로질러야 합니다. 거리는 실측하지 않으며, 선끼리 교차하면 저장하지 않습니다.
5. **이 CCTV 기준선 저장**을 누릅니다. 북쪽·동쪽·남쪽에 각각 저장합니다. 다른 CCTV로 이동하기 전에 저장하세요.
6. 메인에서 영상을 분석한 뒤 결과를 불러옵니다. 메인·화장실 상세·사이니지의 예상 대기시간과 혼잡도는 모두 위 거리 기준을 사용합니다. 대기인원·입장·퇴장 카운팅은 그대로 표시합니다. 영상 위의 점은 마지막 확정 대기자의 발 위치입니다.

| 도달한 가장 먼 기준선 | 혼잡도 | 예상 대기시간 |
| --- | --- | --- |
| 없음 / 5m 미만 | 여유 | 5분 미만 |
| 5m / 10m 미만 | 보통 | 5분 이상 |
| 10m / 15m 미만 | 혼잡 | 10분 이상 |
| 15m | 매우 혼잡 | 15분 이상 |

거리와 대기시간 기준을 숫자로 조절하는 입력은 없습니다. 대시보드의 인원 기반 대기시간 수식과 인원 기반 혼잡도 기준은 제거했습니다. 과거 기록용 평균 이용시간·운영 칸 수·인원 혼잡도 임계값·추천 최소 절감시간 입력도 제거했습니다. 기존 설정 파일의 해당 키는 보존하지만 표시와 계산에 사용하지 않습니다.

사이니지는 현재 사이니지 위치를 출발점으로 `walk`에 저장한 도보시간(초)을 거리 기반 대기시간 범위에 더해 **최종 예상 소요시간**만 표시합니다. 예를 들어 도보 3분과 5분 미만은 8분 미만, 도보 3분과 15분 이상은 18분 이상입니다. 초 단위 값은 반올림하지 않고 함께 표시합니다. 대기시간이나 도보 설정을 확인할 수 없으면 최종 시간도 측정 불가입니다. 실시간 사이니지·지도·정적 HTML 저장에 동일하게 적용하며, 메인·상세·그래프·CSV의 예상 대기시간에는 도보시간을 더하지 않습니다. 합산 결과는 임의 거리 기준 시연용 범위이며 정확한 실제 소요시간이나 가장 빠른 도착을 보장하지 않습니다. 추천과 정렬은 기존의 혼잡 단계 및 동일 단계 도보시간 기준을 유지합니다.

상세 화면의 대기시간 그래프는 현재 CCTV 분석의 거리 구간을 범주형으로 표시합니다. 과거 인원 기록에는 거리 좌표가 없으므로 시간으로 환산하지 않고 측정 불가로 표시합니다. 과거 대기인원 그래프와 입장·퇴장 기록은 유지합니다.

분석 모듈의 `expected_wait_s`와 평균 이용시간·운영 칸 수 설정은 외부 호환성과 내부 인원·가용 칸 추정을 위해 원본 그대로 보존합니다. 대시보드 표시 데이터에서는 `expected_wait_s`를 읽거나 전달하지 않으며, 판정 실패 시 대체값으로 사용하지 않습니다.

## 영상 시각 기반 표시 안정화

- 원시 거리 판정과 안정화된 표시를 구분합니다. 원본 분석 결과·CSV·인원 카운트는 변경하지 않습니다.
- 짧은 판정 실패 또는 단계 변경 확인 중에는 마지막 유효 판정을 **최근 판정 유지**로 표시합니다. 한도는 실제 소스 프레임의 마지막 유효 관측 시각으로부터 영상 시간 **최대 3초**입니다. 무효 기록이나 보류 중인 단계 변경으로 이 시각을 갱신하지 않습니다.
- 영상 시각이 마지막 유효 관측 시각보다 3초를 초과하면, 다음 기록이 오기 전이라도 측정 불가입니다. 유지된 점은 반투명하게 표시합니다.
- 다른 혼잡 단계로 바뀌려면 서로 다른 소스 관측의 연속 유효 기록 2개가 필요합니다. 감소에도 같은 규칙을 사용합니다. 무효 기록 또는 1.1초 초과 기록 간격은 연속 근거를 끊습니다. 첫 유효 관측이나 만료 후 새 유효 관측은 새 기준을 시작합니다.
- 재생 위치를 이동하면 해당 시각 이전 기록만 조회합니다. 화면에서 직전에 본 판정을 저장해 재사용하지 않으므로 되감기·처음부터·새 실행 사이에 판정이 섞이지 않습니다. 일시정지는 영상 시간이 멈추므로 PC 시간이 흘러도 유지 한도가 소진되지 않습니다.
- 메인·상세·사이니지·정적 저장·그래프·대시보드 내보내기는 같은 안정화 결과를 사용합니다. 그래프에는 기록 사이의 3초 만료 지점도 넣습니다. 내보내기에는 원시 혼잡도·판정 표시·마지막 유효 관측 초를 함께 기록합니다.

## 판정과 측정 불가

- 기존 분석기의 확정 대기자와 조건부 후보자의 발 좌표를 원본 프레임 기준 0~1 좌표로 저장합니다. 후보자는 확정 대기자로 승격하지 않으며, 기존 인원·입장·퇴장·잔류 집계에는 합산하지 않습니다.
- 후보자는 대기 ROI 내부, 통행 ROI·제외 구역 외부에서 연속 2초 이상 관측되어야 합니다. 2초 관측 구간의 저속 체류(기존 저속 기준 이하) 또는 가까운 확정 대기자와 동반 이동 근거가 있어야 합니다. 이동 근거는 2초 관측, 2인 신장 이내 거리, 방향 코사인 0.8 이상, 속도 차이 0.15 신장/초 이하, 두 사람 모두 0.7 신장/초 이하입니다. 후보자끼리는 동반 이동 근거로 삼지 않습니다.
- 관측 누락·ROI 이탈은 체류 근거를 초기화합니다. 빠른 통행인·ROI 밖 인원은 제외합니다. 확정자와 포함 후보자 위치를 함께 비교해 마지막 위치를 선정하며, 영상 위에 해당 추적 ID와 확정/후보 구분을 표시합니다.
- 시작점의 반대편까지 대기자가 도달한 기준선 중 가장 먼 선으로 등급을 정합니다. 선의 양 끝점을 뒤집어도 결과는 같습니다. 직선 형태의 대기줄을 대상으로 하며, 굽은 대기줄은 지원하지 않습니다.
- 후보자가 있다는 이유만으로 확정자의 거리 판정을 막지 않습니다. 확정자·조건부 후보자가 전혀 없고 체류 근거 수집 중인 후보자만 있으면 측정 불가입니다. 가림 유예·중복 억제, 포함 대상의 감지 신뢰도 0.5 미만, 가까운 기준선 폭 밖 좌표, 불완전하거나 오래된 관측은 측정 불가입니다. 원근이 다른 먼 기준선의 폭을 입구 근처 사람에게 적용하지 않습니다.
- 좌표가 없는 과거 분석 결과는 인원 수만으로 거리 등급을 추측하지 않습니다. 새 버전으로 재분석해야 합니다.
- 영상이 없으면 격자에서 설정 연습과 저장만 가능합니다. 연습용 선은 실제 영상 결과에 적용되지 않습니다.
- 공통 기준선은 원본 내용의 SHA-256으로 연결됩니다. 동일 원본은 경로·파일명·수정 시각이 달라도 적용하고, 재인코딩/편집본이나 다른 방향의 원본은 자동 연결하지 않습니다. 분석 시작 당시의 식별 정보도 보존합니다.
- 팀 공통 좌표는 `configs/distance_reference.json`에 저장합니다. 기존 `data/settings.json`의 `distance_demo`와 검증된 이전 영상 키도 호환하며 덮어쓰지 않습니다. 기존 분석 CSV 13열은 그대로 유지하고, 좌표는 분석 상세 JSON/SQLite에 보존합니다. 대시보드 CSV 다운로드에는 거리 시연 결과와 표시 문구를 추가합니다. 자세한 공유 방법은 [공통 기준선 안내](../docs/SHARED_DISTANCE_REFERENCE.md)를 확인하세요.

## 검증 범위

합성 좌표로 네 단계와 정확한 경계값, 불확실 상태, 과거 28초 값의 미노출, 카운트 유지, 화면 간 일치와 과거 기록·그래프를 검증했습니다. 실제 저장된 북쪽·동쪽·남쪽 분석 기록도 거리 결과만으로 표시하도록 확인했습니다. 실제 영상에서 각 기준선 도달 판정의 정확도와 브라우저 렌더링의 시각적 확인은 별도로 필요합니다.

테스트 명령은 저장소 최상위에서 실행합니다.

```powershell
python -m unittest discover -s tests -p test_distance_demo.py -v
python -m unittest discover -s tests -p test_distance_app.py -v
python -m unittest discover -s tests -p test_distance_only.py -v
python -m unittest discover -s tests -p test_distance_candidates.py -v
python -m unittest discover -s tests -p test_distance_stability.py -v
python -m unittest discover -s tests -p test_distance_reference.py -v
python -m unittest discover -s tests -p test_signage_time.py -v
```

프런트엔드 자동 테스트는 합성 DOM을 사용합니다. 합성 재생 fixture를 생성한 뒤 실행합니다.

```powershell
python tests/build_distance_fixtures.py
node tests/test_distance_frontend.cjs .local-run/distance-ui-test
node tests/test_distance_stability_frontend.cjs .local-run/distance-ui-test
node tests/test_playback.cjs
```

위 명령은 의존성이 설치된 Python 환경을 활성화한 뒤 실행합니다. 앱은 기존 `run-dashboard.ps1`로 실행합니다. 실행 스크립트는 기존 `-Python` 인수와 `DASHBOARD_PYTHON` 환경변수를 지원하며, `CCTV_DASHBOARD_PYTHON`으로도 환경을 지정할 수 있습니다. 지정하지 않으면 프로젝트 가상환경 등을 탐색합니다. 파일 폴링 감지와 자동 재실행을 활성화합니다. 실행 로그와 수정 전 파일 백업은 `.local-run`에 있습니다.
