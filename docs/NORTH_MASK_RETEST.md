## 마스크에서 확인한 문제

현재 제외 마스크는 영상 픽셀을 지우는 전처리 마스크가 아닙니다. 원본 전체를 YOLO와 ByteTrack이 처리한 다음, **박스 하단 중앙점이 제외 폴리곤 안에 들어올 때** 출입·대기 규칙에서 제외합니다.

대기 구역과 통행/제외 구역의 겹침은 픽셀 격자 검사에서 0이었습니다. 실제 관측 하단점에서도 대기 구역 안에 있으면서 통행/제외 구역 때문에 차단된 기록은 0이었습니다. 이 부분의 구역 충돌은 확인되지 않았습니다.

하지만 **표지 그림을 제외하는 첫 번째 마스크는 오탐 박스의 하단점까지 덮지 못했습니다.** 직접 확인한 ID 8은 0초에서 여자 표지 그림을 탐지한 박스이며 하단은 y≈269.5px, 5초에는 y≈280.9px입니다. 현재 제외 구역의 가장 아래 꼭짓점은 y≈249.5px입니다. 그림의 몸통을 덮는 것만으로 이 오탐을 제외할 수 없습니다.

이번 240프레임의 전체 추적 관측 2,981개 기록 중 제외 마스크에 들어온 하단점은 **0개**였습니다. 이는 사람 수가 아니라 프레임별 관측 기록 수입니다. 원본과 박스를 비교한 표지 그림 오탐이 마스크 밖에 남는 실제 사례와 함께 해석해야 합니다.

ID 8은 5초에 대기 후보로 들어갔지만 이번 구간에서 confirmed가 된 프레임은 없습니다. 최대 느린 이동 증거는 약 1.542초였습니다. 따라서 5초의 집계 2명에 표지 그림이 포함됐다고 판단하지 않았습니다. 마스크를 그대로 두면 후보 생성과 추적에는 오탐이 남습니다.

## 확인 이미지와 다음 수정 기준

마스크 확인 자료는 `inspections/north_mask_review_20261014_140617_3ae3930f`에 있습니다.

- `poster_mask_miss.png`: 0초/5초 표지 그림 오탐 박스, 제외 마스크, 제외되지 않은 하단점 확대 비교.
- `masks_000000.png`, `masks_000120.png`, `masks_000171.png`, `masks_000216.png`, `masks_000239.png`: 현재 마스크와 모든 관측 하단점. 초록 점은 대기 구역 안의 판정 가능한 점이며 대기 확정을 뜻하지 않음.
- `mask_check.json`, `observed_anchor_masks.csv`: 마스크 겹침과 프레임별 포함 여부.
- `retest_comparison.json`: 이전 결과 비교, 장치, 테스트, 사용자 설정 보존 확인.

ID 6의 새 구역/궤적 자료는 `inspections/north_id6_review_20261014_140303_cb670281`에 있습니다. `zones_trajectory_korean.png`와 `state_replay.json`을 확인하세요. 경계가 그대로여서 내부 구역만 수정해도 기존 하단 흔들림·ID 대상 변경 문제가 해결되지 않았습니다.

표지 제외 구역은 **오탐 박스의 흰 하단점**까지 포함하도록 사용자가 검토해야 합니다. 바로 옆 실제 대기자의 발까지 포함하면 정상 사람도 빠지므로 크게 아래로 넓히는 방식은 피하고, 여러 시각의 박스 하단과 실제 발을 함께 비교하세요. 좌표를 임의로 확정하지 않았습니다. 마우스 창에서 Tab으로 `excluded_zones`에 이동한 뒤 수정할 수 있으며 R은 첫 번째 구역 하나가 아니라 저장된 제외 구역 전체를 지우므로 주의하세요.

```powershell
& .\.venv\Scripts\python.exe -m cctv configure --config configs/north.json --time 0 --max-width 1100 --max-height 620
```

수정한 경우 P로 전체 구역을 확인한 뒤 S로 저장합니다. 경계·양쪽 확인 구역은 실제 발이 보이는 바닥 기준으로 별도 검토해야 합니다. `side_confirm_s`를 먼저 낮추지 않습니다. 북쪽 검증이 안정되기 전에는 남쪽·동쪽 집계 검증으로 확대하지 않습니다.
