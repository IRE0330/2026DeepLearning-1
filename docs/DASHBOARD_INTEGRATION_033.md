# 대시보드 0.3.3 통합 검증 (2026-10-28)

설치·실행은 [저장소 시작 안내](../README.md)를 따릅니다. 원본 개발 폴더·미커밋 변경·기존 환경과 결과를 보존하고 별도 복제본·새 Python 환경에서 검증했습니다.

## 통합 범위

- 0.3.3의 `gpu_profile.py`, 검증 보조 `waiting_audit.py`, north-gpu-s JSON, 관련 테스트와 package-data를 선별 반영했습니다. 팀원 수정 `core.py`·`distance_candidates.py`와 환경별 마스킹·판정·기록 정책은 유지했습니다.
- 기본 n의 사용자 영상·구역 JSON·장치·출력 전달을 유지했습니다. 명시적 north-gpu-s만 북쪽 s, 동쪽·남쪽은 n이며 순차 실행합니다. s는 공식 파일 무결성·cuda:0·번들 북쪽 구역을 실행 전에 검사합니다. 사용자 북쪽 JSON은 무시하지 않고 지원 불가로 안내합니다.
- 실행 Python의 설치 버전 0.3.3과 실제 `cctv.api` 경로가 현재 `cctv-analysis/src/cctv`인지 검사합니다. 이전 `busan_restroom_integrated` 소스와 구버전 설치를 혼용하지 않습니다.
- 시작·중복 시작 차단·상태·레코드 수신·중지를 유지하고 Windows SQLite 연결 종료를 보완했습니다. 설정 패널에는 재실행 시 열림 상태를 유지하는 key를 추가했습니다. 예측 전달은 disabled입니다.

## 자동 검증

- 루트 Python 테스트 **153개**, 분석 패키지 테스트 **108개** 통과. 기본 n/사용자 설정, 북쪽 s 분리, 버전·실제 import·editable 설치 원본, 설치 manifest와 외부 작업 폴더의 JSON resource, 중복 시작·레코드 수신·중지, 13열·API 계약, 기존 판정·기록 간격을 확인했습니다.
- 재생·거리 표시·브라우저/Python 판정 일치 JavaScript 테스트 3개 묶음 통과. 기존 테스트의 오래된 메뉴 번호·재생 키 정규식·시뮬레이션 시계 fixture·제거된 iframe reset 컨트롤 참조를 현재 화면에 맞췄습니다. 제품의 거리·대기시간·재생 계산은 변경하지 않았습니다.
- 같은 Python의 `pip check` 통과. 소스 editable 설치로 충분하여 배포용 wheel/ZIP은 새로 만들지 않았습니다.

## 실제 추론과 브라우저

Windows x64, Python 3.13.9, Streamlit 1.66.0, Ultralytics 8.4.177, torch 2.14.1+cu132, RTX 4060, Chrome·Playwright CLI 0.1.22에서 확인했습니다. 기존 개발 영상의 처음 약 12초를 원래 해상도·프레임으로 재인코딩 없이 remux한 별도 MP4를 사용했습니다. 원본 영상은 변경하지 않았습니다.

| 실행 | 북쪽 | 동쪽 | 남쪽 | 수신 레코드 |
|---|---|---|---|---|
| 기본 n · CPU · 처음 5초 | n / 120프레임 | n / 150프레임 | n / 150프레임 | 각 5개 |
| north-gpu-s · cuda:0 · 약 12초 | s / 288프레임 | n / 365프레임 | n / 365프레임 | 각 12개 |
| 실행 중 브라우저 중지 | s / 274프레임에서 stopped | 시작 안 됨 | 시작 안 됨 | 북쪽 11개 보존 |

모델 경로뿐 아니라 추론 backend의 실제 parameter device와 처리 프레임·수신 레코드를 확인했습니다. CSV는 모든 행 13열, 예측 전달 disabled였습니다. 화면 표시나 모의 테스트를 실제 추론으로 간주하지 않았습니다.

Playwright로 화면 열기, n↔북쪽 s 선택, 시작·진행·결과 갱신·중지·시작 버튼 비활성화, 메인→상세→사이니지→메인 전환을 확인했습니다. 세 영상은 readyState 4, 실제 재생 시간 증가·일시정지·미디어 오류 없음이 확인됐고 화면 전환 후 재생 위치가 보존됐습니다. 임시 시연 기준선을 이용한 같은 분석 시점의 거리·대기시간 표시가 세 화면에서 일치했습니다. 이는 실측 거리/대기시간 정확도 검증이 아닙니다.

브라우저에서 영상 누락, s 가중치 누락·다른 가중치, CPU+s, 사용자 북쪽 JSON을 실행 전에 거절했습니다. 이 실패 입력들은 작업을 생성하지 않았습니다. CUDA가 없는 경우는 사전 검사 단위 테스트로 검증했으며, 이번 실제 GPU 실행 환경에는 CUDA가 있습니다. MPS 실제 실행은 하지 않았습니다.

## 배포물과 제한

`feature/restroom-dashboard1023`의 구버전 추적 배포물은 `dist/busan_cctv_analysis-0.3.2-py3-none-any.whl` 하나입니다. 현재 실행 스크립트는 이를 참조하지 않으며 소스 설치를 검증했습니다. [기존 0.3.2 Release](https://github.com/IRE0330/2026DeepLearning-1/releases/tag/cctv-analysis-v0.3.2)의 같은 wheel과 바이트 일치를 확인한 뒤 Git 추적만 제거합니다. 로컬 파일·기존 Release의 wheel/ZIP·태그·Git 이력과 이전 소스 폴더는 보존합니다.

main에는 조사 대상인 추적 wheel·ZIP·압축 배포물이 없어 제거할 경로가 없습니다. main의 현재 0.3.2 분석 소스와 팀 자료는 유지하며 통합 브랜치를 main으로 merge하지 않습니다. 따라서 main 정리 커밋·push·PR은 필요하지 않습니다.

기존 단일 입력 시험과 세 환경 동시 분석 성능은 다릅니다. **세 환경 동시 실시간 처리는 보장하지 않습니다.** 실제 CCTV·네트워크·장시간 운영은 미검증이고, 정확도 수치는 개발 영상 평가로 다른 영상의 성능을 보장하지 않습니다. 내부 인원·빈 칸·대기시간에는 가정이 포함됩니다. 새 검증 환경에서 MySQL 연결은 구성하지 않아 열차 DB 기능을 검증하지 않았습니다. 예측 모델 코드·학습·실제 예측 연동은 이번 범위에 포함하지 않습니다.
