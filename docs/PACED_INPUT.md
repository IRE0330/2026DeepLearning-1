# 실제 재생속도 입력 모사와 CSV 기록 지연 — 2026-10-17

북쪽 단일 입력은 전체 영상을 완료했고, CSV 105행의 기록 지연이 모두 이번 시험 목표인1초 이내였습니다. 세 환경 동시 입력은 적체가 계속 증가해 사전 보호 기준으로 자동 중단했습니다. 두 시험 모두 처리 구간에서 같은 GPU의 비제한 속도 결과와 CSV·출입·프레임별 진단이 일치했습니다. 실제 카메라/네트워크 입력이나 수동 정답 정확도를 검증한 결과는 아닙니다.

## 실행 조건과 구현

기존 `.venv-gpu`, RTX4060 8GB, `cuda:0`, FP32/half:false, YOLO11n/imgsz640/conf0.1/iou0.7을 사용했습니다. 실제 추론 backend의 가중치와 결과 텐서가 cuda:0, 가중치 dtype이 torch.float32임을 각 summary에서 확인했습니다. 모델·최종 마스킹·출입/대기/중복 억제·계산·공유13열·운영 설정은 변경하지 않았습니다.

환경 설정 → 영상 등록 목록 → demo 프로필 → 시험 출력 옵션 순으로 적용합니다. 실제 적용값은 북쪽 초기29명/27칸, 남쪽3명/19칸, 동쪽3명/23칸, 평균105초, 시연 기준2026-10-14T00:00:00+09:00입니다. 초기값은 영상 시작 가정이며 이후 확정 출입으로 변합니다. demo1초 기록/한국시간 구간 시작 기준 정시3600초 분할, prediction disabled, 영상/오버레이 출력 없음, 전체 프레임 진단을 유지합니다. 운영10초 기록은 보존합니다.

새 `simulate-input` 명령은 저장 영상을 대상으로만 합니다. 각 환경이 별도 프로세스의 Detector/ByteTrack/Counter/CSV를 가집니다. ByteTrack의 전역 ID 카운터도 프로세스로 분리합니다. 동시 시험은 순차 batch가 아니며, 세 프로세스가 공통 입력 시작 monotonic 시각을 사용합니다. GPU 추론 경로(`observe`, 전처리·탐지·후처리/추적 포함)는 공유 semaphore 한 자리로 직렬화합니다. GPU 배치 추론이나 실시간 CCTV 수신 서버를 구현한 것은 아닙니다.

입력 전 전체 PTS/CFR 검사·영상 해시 확인·모델 로딩·같은 해상도의 더미 이미지 GPU 워밍업·CUDA synchronize를 끝냅니다. 워밍업은 tracker.update를 호출하지 않습니다. 각 준비 완료시각과 공통 준비 완료시각을 기록하고, 공통 기준에100ms 여유를 둔 뒤 공급합니다. 원본 전체 PTS 검사로 CFR을 확인했으므로 정규화 원본 시각 `프레임 번호/FPS`를 사용합니다.

`입력 예정 monotonic = 공통 입력 시작 + 원본 프레임 시각`이며, 늦어져도 기준을 이동하지 않습니다. 영상별 생산 스레드는 한 프레임씩 디코딩해 예정시각까지 기다린 뒤 크기8의 큐에 넣습니다. 큐가 차면 생산자가 기다리며 프레임을 버리지 않습니다. 입력 측 버퍼는 큐8+생산 중1+소비 중1이며, 이 수는 모델이 보유하는 이미지/텐서·CUDA context/디코더 내부 버퍼를 제외한 범위입니다. 전체 영상을 이미지 배열로 미리 적재하지 않습니다. 사전 검사는 전체 프레임의 시각 메타데이터만 보유합니다.

기존 IntervalSampler의 상태 선택과 이벤트 소속은 유지합니다. 양쪽 CSV 쓰기 전에 기록 경계의 고정 예정시각까지 기다립니다. 소스 상태는 경계 이하이며 미래 프레임을 사용하지 않습니다. 마지막 CFR 프레임이 덮는 재생시간까지 EOF도 기다리므로, 정확한 정수 초 종료에서도 조기 저장하지 않습니다. 정수 초 종료는 마지막 정기 행에 포함하고1초 미만 꼬리는 remainder/final 파일에 보존합니다. 동쪽90초 종료 경계는 최소 테스트에서 확인했고, 이번 동시 실행의 동쪽은 중단되어90초에 도달하지 않았습니다.

대기는 이번 **재생속도 입력 모사**에만 있습니다. 기존 analyze의 최대 처리속도 모드에 sleep을 추가하지 않았습니다. unpaced 비교 명령은 같은 워밍업/분석/출력을 사용하고 공급 시각 대기만 생략합니다.

## 측정 정의

모든 차이는 `time.perf_counter_ns()`를 사용합니다. 벽시계/파일 수정시각으로 지연을 계산하지 않습니다. 가상 촬영일시는 공유 CSV의 시각을 구성하는 용도입니다.

- `csv_latency.csv`: record_id/CSV 경로·행 번호, 영상 구간 종료시각, 소스 프레임 시각, 고정 입력 기준, 기록 경계 예정 monotonic, 공유 CSV flush 완료 monotonic, 기록 지연, 이전 저장 이후 간격을 보존합니다.
- **기록 지연 = 공유 CSV flush 완료 − (공통 입력 시작 + 영상 기록 경계)**. 준비시간은 이 값에 포함하지 않습니다. flush는 Python 파일 핸들의 flush 반환이며 fsync/물리 디스크 영구 기록 또는 외부 소비자 수신 완료를 뜻하지 않습니다.
- `frame_arrivals.csv`: 프레임 번호/원본 정규화 시각, 예정·공급·큐 삽입·꺼냄·GPU 시작/종료 시각, GPU 대기, 큐 깊이, 예정 도착했지만 아직 완료하지 못한 프레임 수를 기록합니다.
- `timing_events.jsonl`, `timing_summary.json`: 검사/모델/워밍업/준비/첫 프레임/종료와 통계입니다. 준비시간의 시작은 **자식 분석 함수 진입**이며 부모 CLI·Python 인터프리터 시작 시간은 제외합니다. 첫 모델 실제 프레임 처리 비용은 지속 처리에 포함합니다.
- `resource_samples.jsonl`:0.5초마다 장치 전체 NVML 사용량·이용률과 환경별 큐/완료/torch 메모리를 기록합니다. 열 의미는 experiment_summary.metric_columns입니다. CUDA 작업을 하지 않는 부모가 수집합니다.

사전 자동 중단 기준은 **프레임 GPU 처리 시작 지연>5초가10초 연속 지속**, 또는 **한 번이라도>15초**입니다. 어느 환경에서든 충족하면 전체 공급을 중단하고 완료한 연속 구간·CSV·이벤트·진단·잔여/최종 상태를 닫아 보존합니다. 원본의 나머지 구간은 미처리로 보고하며 임의 누락 후 계속 처리하지 않습니다. 이 보호 기준과 프로젝트의 기록 지연1초 목표는 서로 다릅니다.

## 수동 카운팅 검토 준비

`ground_truth/{north,south,east}/{events,waiting,inside}.csv`와 metadata는 그대로 보존했습니다. 수동 출입/대기 정답은 아직 없습니다. 자동 결과를 정답 양식에 채우거나 정확도 수치를 만들지 않았습니다.

검토 후보 전체 목록은 `inspections/paced_input_20261017_221034_565c3b13/review/manual_review_candidates.csv`입니다. **자동 로그에서 고른 검토 위치**이며 정답이 아닙니다. 북쪽은2~9초 대기/가림,13~23초 출입,30~36초 세부 상태 차이,95~105초 후반 출입을 우선 보세요. 남쪽은5~10초 가림,15~19초 퇴장,28~35초 대기/입장,47~52초 입장,60~64초 퇴장,88초 이후 미확정 후보가 있습니다. 동쪽은7~24초 출입/가림,40~47초 대기,53~57·62~66·70~74초 퇴장을 검토합니다. 목록의 모든 행동은 원본으로 사람이 확인해야 합니다.

원본을 재생하고 `events.csv`에 화장실ID, 영상 시작 기준 초(가능하면 소수 초), 방향(entry=외부→내부, exit=내부→외부)를 기록하세요. 실제 유한 경계를 통과한 시점을 일관되게 기록하고 되돌아감/가림으로 확인 불가한 사례는 별도 메모하세요. 평가기는 자동 확정시각과 기본±1초로 매칭하므로 경계 통과시각과 자동 확정의 차이도 검토해야 합니다. 후보 구간만 라벨링했다면 annotated_start/end를 그 구간으로 제한하고, 해당 구간의 모든 출입을 빠짐없이 확인하기 전 events_complete=true로 두지 마세요. 자동 후보 밖의 누락도 찾는 전체 검토가 별도로 필요합니다.

`waiting.csv`에는 영상의 **정수 초 시점**(예:2,3,4초)의 외부 대기 인원을 사람이 세어 기록합니다. 새로 줄에 선 사람과 기존 대기자를 포함하고 통행인은 제외하며 같은 사람은 한 번만 셉니다. 가림 전후를 연속 재생해 같은 사람인지 확인하되, 보이지 않아 확인 불가능하면 추측 숫자를 정답으로 넣지 말고 별도 메모하세요. 자동 candidate/confirmed/가림 유예 수치를 베끼지 않습니다. metadata의 대기 정책과 라벨 정의를 맞추고 실제 내부 정답이 없으면 inside.csv는 비워둡니다. demo 초기29/3/3명은 실제 내부 정답이 아닙니다.

다음 작업은 현재 GPU 직렬 경로에서 전처리/추적/진단/추론 시간을 나눠 병목을 측정하고, 필요한 CPU 작업을 GPU 잠금 밖으로 옮기는 등 동시 처리 구조를 개선한 뒤 같은 보호 기준으로 재시험하는 것입니다. 모델·정밀도·마스킹·프레임 생략을 바꾸어 이번 결과와 혼합하지 않습니다. 실제 CCTV의 캡처/네트워크/장시간 장애·재연결과 수동 정답 정확도 평가는 별도입니다. 실제 예측모델은 미연동이며 외부 전송·Git push는 하지 않았습니다.
