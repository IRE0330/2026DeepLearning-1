## 현재 완료 기능

- 사전학습 YOLO11n person 탐지 → ByteTrack → 공통 출입/대기 규칙 → 집계. 추가 학습이나 성별/외형에 따른 이용 목적 추론 없음.
- 환경별 사용자 경계·입장방향·양쪽 확인구역·대기/통행/제외구역, 마우스 설정/검사/미리보기.
- 유한 경계와 연속 확인 구역의 확정 출입, 되돌아감/흔들림 후보 취소, 실제 재입장 허용, 관측 가림 공백의 미확정 처리.
- 외부 대기는 관측 candidate+confirmed, 중복 억제 후 confirmed 가림 유예. candidate에 새 가림 유예를 주지 않고 같은 ID를 중복 집계하지 않음. 확정 입장은 같은 프레임 외부 대기에서 제외.
- 내부 원시 인원=초기값+분석 시작 이후 누적 입장−퇴장. 미설정/0 구분, 음수 보존/상태 기록. 평균시간 자동 차감/칸 수 제한 없음.
- 추정 내부대기=MAX(내부−운영 총칸 수,0), 현재대기=외부+내부대기=전체Q. 빈칸 추정=MAX(운영 총칸 수−내부,0). 실제 점유를 관측한 값이 아님.
- 사용자 가정 예상시간=(Q+1)×평균 이용시간/운영 총칸 수. 현재 빈 칸을 분모로 쓰지 않으며 N=0/null이면 계산 불가. 값은 상세/영상에 저장하고 공유13열에는 넣지 않음.
- 명시적인 다중 영상 등록·순차 batch, 영상별 상태 초기화, 실패 계속/중복 등록 억제/실행별 고유 폴더.
- UTF-8 BOM13열 공유 CSV, 화장실별·촬영종료 한국 날짜별 분리/정렬/매 기록 저장. 이벤트/시계열/진단/상세/잔여/최종/설정 사본 보존.
- 빈 정답에는 정확도 수치를 만들지 않는 평가 경로. 완전한 출입 정답의 동일방향±1초 일대일 매칭, 동일 시각 외부대기 MAE 등.
- MICC RGB 순차 추적 보조 점검. 원본 FPS 미확인으로 프레임 번호를 기록하고 화장실 출입/대기 정답으로 사용하지 않음.

MVP 시연 기준은 **2026-10-14T00:00:00+09:00**, 북쪽 **초기29명·운영27칸·평균105초**입니다. 실제 관측 내부 인원/촬영일시 정답이 아닌 가상 시나리오 가정입니다. 다음날 실행해도 이 설정 날짜는 자동으로 바뀌지 않습니다. 날짜 변경이 필요하면 사용자 판단으로 프로필을 편집합니다. 현재는 그대로 유지했습니다.

## 남은 문제

- 실제 north/south/east의 수동 events/waiting/inside 정답 CSV는0행이고 정확도 평가는 미완료입니다. 시연 CSV/합성 예시를 실제 정답으로 복사하지 않습니다. 세 영상은 개발용이므로 일반화 정확도를 주장하지 않습니다.
- 북쪽 과거 영상의 ID6 사례에서 발 기준점 흔들림과 서로 다른 사람으로 ID가 이어지는 문제를 확인했습니다. 구역 확인 없이 side_confirm_s를 먼저 낮추지 않습니다. 현재 북쪽 전체 진단에는 관측 공백·가림 억제·취소 출입 후보가 있으며 후반 구도 정합성도 추가 검토가 필요합니다.
- 남쪽 최종 상태에는 미확정 출입 후보, 남쪽/동쪽에는 관측 공백·미확정 이력이 있습니다. 화면에서 사라짐만으로 출입을 추정하지 않아 실제 누락 가능성을 수동 확인해야 합니다.
- candidate 포함으로 짧은 통행/체류도 외부대기로 셀 수 있으며 confirmed-only보다 오탐 가능성이 높습니다. 제외 구역·하단점·부분 가림·ID 변경과 대기 유예 중복 억제를 계속 검토합니다.
- 내부 실제 인원과 남쪽/동쪽 운영 칸 수가 없어 관련 계산은 빈 칸입니다. 실제 칸 점유나 대기시간을 관측한 시스템이 아닙니다.
- **예측모델 호출/전송/연동·미래 혼잡도 예측·분산 안내·웹 UI/배포는 미구현**입니다. 생성/CSV 저장은 분리돼 있으며 연결 위치·row/detail 계약·완성 행/고유키/영속 중복 억제 설계만 `PREDICTION_INTEGRATION.md`에 있습니다.

## 내일 이어가기

현재 개발 폴더에서는 새 clone 없이 아래 명령으로 브랜치/변경을 확인합니다. `git pull --ff-only`는 로컬 변경을 임의로 덮어쓰지 않는 방식이며 충돌 시 확인 후 진행합니다.

```powershell
git switch mvp/busan-cctv-20261014
git status
git pull --ff-only
& .\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

팀원 새 PC는 README1절의 clone/설치 후 별도 영상과 가중치를 배치합니다. 같은 원본/구도이면 저장된 설정을 활용하고, 구도가 달라졌다면 환경별로 재설정합니다. 역사적 검증 보조 스크립트는 별도 결과/검사 자료가 필요하며 일부 한국어 그림 스크립트는 Windows 맑은 고딕 시스템 폰트를 사용합니다.

```powershell
& .\.venv\Scripts\python.exe -m cctv validate --config configs/north.json
& .\.venv\Scripts\python.exe -m cctv preview --config configs/north.json --time 5
& .\.venv\Scripts\python.exe -m cctv analyze --config configs/north.json --profile demo --start 0 --end 10
```

등록 영상 전체 MVP1초 분석/운영10초 분석을 선택하는 명령입니다. 영상/구역/초기값을 확인하고 필요한 경우에만 실행합니다.

```powershell
& .\.venv\Scripts\python.exe -m cctv batch --registry configs/video_registry.json --profile demo
& .\.venv\Scripts\python.exe -m cctv batch --registry configs/video_registry.json --profile operating
```

결과 폴더의 `batch_summary.json`, `shared/환경_날짜.csv`, 영상별 annotated/events/timeseries/diagnostics/final/remainder를 확인합니다. 다음 개발은 실제 실패 구간 수동 검토 → 정답 작성 → 평가입니다. 초기값/칸 수/실제 촬영시각은 확인한 경우만 입력하고 예측모델 연결은 별도 작업으로 진행합니다.
