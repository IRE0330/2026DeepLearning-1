# CCTV 표시 통합 안내

GitHub `feature/restroom-dashboard1023`의 548904d 최신 UI를 기준으로 CCTV 표시만 추가했다. 메뉴, 레이아웃, 색상, 카드, 지도, 전체화면, 공통 재생 코드는 유지한다. 플랫폼 예측 CSV·도착 시각 조회·추천·도보시간 처리, 예측모델 및 열차 DB 경로는 변경하지 않는다. CCTV 도보 합산은 `cctv_presentation.py`에서 분리하며 공용 `signage_time.py`는 유지한다.

## 설정과 조작

- 사용자가 2026-10-28 저장한 환경별 좌표를 기존 `configs/distance_reference.json`에 반영했다. 기존 영상 식별 검증과 별칭을 유지하며 새 해시 목록은 생성하지 않는다.
- 북쪽은 5·10·15m를 사용한다. 남쪽·신관은 5·10m와 저장한 연결 경계를 사용한다. 남쪽·신관의 15m 좌표는 보존하고 판정·영상 표시에서 제외한다. 영상별 기존 지문 검증을 통과해야 해당 환경 설정을 적용한다.
- 메인 대시보드의 영상 및 화장실 상세에서 활성 기준선·시작점·보라색 연결 경계를 확인한다. 기준선 편집 시 기존 설정의 로컬 사본을 먼저 저장하며 비활성 15m와 경계 좌표는 보존한다. 현재 추가 좌표 입력은 필요 없다.
- 기존 Python 환경을 지정하여 저장소 루트에서 `./run-dashboard.ps1 -Python <유효한-python.exe-경로>`로 실행한다. 원래 폴더의 `.venv-dashboard/Scripts/python.exe`를 재사용할 수 있다. 기본 주소는 `http://localhost:8501`이다.

## CCTV 표시 정책

남쪽·신관은 10m 너머의 확정 대기열과 지정된 화면 경계 접촉을 모두 확인할 때만 overflow 후보가 된다. 일반 통행인·단독 접촉·탐지 누락·경과시간만으로 판정하지 않는다. 기본 3초의 유효 연속 관측으로 확정·해제하며 환경별 `overflow_seconds`로 조정한다. 가림·미관측은 증거 시간에 합산하지 않는다. 화면 밖 인원·거리를 생성하지 않는다.

overflow의 **대기 15분 이상은 화면 범위 초과에 대한 MVP 시연 가정**이다. 실제 15m 관측 또는 검증된 대기시간 하한이 아니다. 사이니지에 ‘시연 추정’을 표시한다. CCTV 총 소요시간에는 도보를 더해 하한을 유지한다(도보 2분이면 총 17분 이상). overflow·유지값·미측정이 있으면 보수적으로 추천을 중단한다. 정상 구간의 원격 최신 대기시간 밴드는 유지한다.

분석불가 또는 갱신 중단 시 마지막 유효값(overflow 포함)·원래 영상 관측시각을 유지하고 ‘갱신 지연’을 표시한다. 최초 정상값이 없으면 ‘대기정보 확인 중’이다. 정상 0값과 결측은 구별한다. 복귀에는 새로운 유효 연속 관측이 필요하다. 실행·영상별 독립 재생 자료를 사용하여 탐색·새 실행 시 이전 값이 섞이지 않는다. 정상 파일 종료는 ‘재생 종료’로 표시한다. 유지값은 내보내기·이력에 새 정상 관측으로 기록하지 않는다. 분석 CSV 13열 및 원본 기록은 변경하지 않는다.

## 메뉴와 0명 표시 업데이트

‘혼잡도 예측모델’ 메뉴와 페이지 진입 연결만 제거했다. 기존 세션이 이 메뉴를 선택했으면 메인으로 이동한다. 모델 소스·데이터·의존성 및 저장 예측 결과는 유지한다. 나머지 메뉴 7개와 버튼 키·디자인을 유지한다.

대시보드·상세·CCTV 실시간 사이니지는 같은 브라우저 상태 판정 함수(`distanceState`)를 사용한다. 유효한 마지막 정상 관측의 **전체 대기인원**이 0명이면 ‘대기 인원 없음’, 1명 이상이면 기존 거리 혼잡도 문구를 표시한다. 외부 대기만 0명인 경우나 결측을 전체 0명으로 간주하지 않는다. 지연 시 마지막 정상 상태와 시각을 유지한다. 색상·대기시간 계산·추천·CSV·플랫폼 예측은 변경하지 않았다.

업데이트 후 실행 중인 Streamlit을 정상 종료하고 다시 실행해 이전 Python 표시 모듈이 남지 않게 한다. 저장소 루트에서 `git pull --ff-only origin feature/restroom-dashboard1023` 후 `./run-dashboard.ps1 -Python <기존-가상환경의-python.exe>`로 실행한다. 브라우저도 새로고침한다. 새 환경 설치나 전체 재분석은 필요 없다.

신관의 기존 실제 영상 0·10·20초를 같은 시각으로 맞춰 대시보드·상세·CCTV 사이니지의 문구 일치 및 재생·앞뒤 탐색·화면 전환을 Playwright로 확인했다. 0명·1명 이상·내부 대기·결측·갱신 지연 조건은 별도의 모델 없는 상태 시험으로 확인한다. 실제 overflow 양성·해제 미검증 제한은 그대로다.

## 최초 통합 검증과 한계

- 원격 최신 UI와 통합 UI를 Playwright로 비교했다. 메뉴 8개, 카드 스타일, 3개 영상 재생·일시정지, 전체화면, 플랫폼 CSV 재생·도착 시각 조회·추천을 확인했다. 플랫폼 사이니지 캡처는 픽셀 단위로 일치했다.
- 실제 기존 영상의 원본 관측 289행(북쪽 105·신관 90·남쪽 94)을 새 좌표로 다시 계산했다. 영상 연결 일치, 환경별 활성 선과 경계 겹쳐보기, 마지막 정상값 유지(41·9·7행)를 확인했다. 원본 DB·관측·CSV는 읽기 전용이며 전체 YOLO 재분석은 하지 않았다.
- 남쪽·신관 기존 관측의 확정 대기 좌표가 0개여서 **실제 overflow 양성·해제는 미검증**이다. 이를 확인한 영상이라고 주장하지 않는다. 별도의 상태 주입 시험으로 통행인 제외, 짧은/지속 접촉, 확정·해제, 가림, 마지막 값 유지, 최초 결측/0값, 복귀, 탐색, 새 실행, 종료 및 ‘이상’ 합산을 확인했다.
- Playwright 비교는 자격정보를 읽지 않는 별도 로컬 실행으로 수행했다. 열차 DB 연결과 새 모델 추론은 검증 범위에서 제외했다. 모델 무결성 검증 코드는 유지한다.
